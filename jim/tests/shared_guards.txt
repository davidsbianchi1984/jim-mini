# status: manifest — 425 guards carried by all three products
#
# The questions QRME, JIM-mini and PDI all ask. One test-function name per
# line, present in every one of the three suites.
#
# ## Why a manifest and not a comparison
#
# The three products are separate repositories and are rarely checked out
# together, so a live comparison skips in CI — and a check that skips is a
# check that is not running. This file lets each product verify its own half
# with nothing but itself: every name below must exist in this suite.
# Deleting a guard from one product now fails in that product, on its own, at
# the moment it happens.
#
# The test also does the live three-way comparison whenever the siblings *are*
# on disk, and that is what keeps this file honest.
#
# ## What this file compares, and what it does not
#
# Names. Not behaviour. A guard ported under a different function name reads
# as missing, and one that kept its name while its body was gutted reads as
# present. Both are real limits, stated here rather than discovered later:
# PDI's health endpoint does report its version, under a test called something
# else, and this file would call that a divergence if it were not recorded as
# one in guard_divergences.txt.
#
# What it catches is the thing that actually happens: a fix made in one
# product and never carried across. 0.59.1 found `serve` opening CORS for the
# local console in two products and not the third, so PDI's packaged console
# could not reach its own API from source — measured over HTTP, a preflight
# answered 405 with no access-control headers at all.
#
# This file may grow. A name leaving it is a guard deleted from all three, or
# one that drifted out of a single product, and both should be deliberate.
