# ## How staleness is decided, and the two ways it was decided wrongly
#
# A body is stale when its prose **opens with** the line in `# frozen-opens:`
# above. That line is per product and lives here, so the workflows read it
# rather than carrying a copy.
#
# The first guards written for this asked whether the body contained the string
# `414 tests passing` anywhere. That was wrong twice over, and both showed up on
# the first real backfill:
#
#   * It is **PDI's** number. QRME's and JIM-mini's frozen bodies carry their
#     own counts, so the sweep reported zero stale in two products while 112
#     and 113 remained — a check that passed by being blind.
#   * It matched any body that merely **quoted** the phrase. PDI's own
#     `app-v0.60.8` notes describe this finding, so a correct release failed
#     the check for saying what it fixed.
#
#     asked     does this body contain the sentinel
#     mattered  does this body open as the frozen one does
#
# Opening-line matching answers the second question. A release note is free to
# discuss the frozen body; it may not *be* it.
#
# ## What a row means
#
# One row per stale release. A row leaves when that release's body is rebuilt
# from its own CHANGELOG entry by `backfill-release-bodies.yml`. The ceiling may
# only fall.
#
# A release deliberately left alone **keeps its row with the reason on it**,
# rather than becoming an exemption in code where nobody reads it again.
# `app-v0.24.0` is that row and always will be: its body *is* the v0.24.0
# notes, right for it and wrong for the 411 that inherited it.
#
#
# ## What this file counts, and why the count is zero
#
# The ceiling counts releases **still to repair**. It reached zero when the
# last inherited body was rebuilt.
#
# It does not count `app-v0.24.0`, which sits under `# kept:` below. That
# release was never a defect: its body *is* the v0.24.0 notes, right for it and
# wrong only for the 411 that inherited it. Backfilling it would replace a
# correct body with a duplicate of the changelog to make a number look tidier.
#
#     asked     how many rows are left
#     mattered  how many releases are still wrong
#
# So the kept release moved out of the count rather than out of the file. A
# deliberate decision belongs where the next person reading this will see it,
# not inside a guard as an exemption, and not deleted because it was
# inconvenient to a total.
#
# The file stays at zero. An empty file with no `# kept:` line would say *no
# release was ever stale*, which is the opposite of what happened here: 412 of
# 530 were, across the three products, for a hundred and thirty-four releases.
