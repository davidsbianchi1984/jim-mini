# ## What these rows are
#
# `RELEASE_NOTES.md` was last written for v0.24.0. `sync-release-notes.yml`
# published it verbatim over every release body after it, waiting for the

# and the design was the defect: a curated body was written at tag time,
# published, and replaced by a file thirty-six minor versions behind.
#
#     asked     which workflow owns the release body
#     mattered  does the body say what shipped
#
# **412 of 530** releases across the three products, one identical body
# spanning 134 tags. This product holds 138 of them. Both the file and the
# workflow are deleted as of 0.60.8, and `app-v0.60.8` is the first release
# that is not on this list — its curated body survived untouched, which is how
# the deletion was confirmed to work.
#
# ## What a row means, and what shrinking means
#
# One row per release still carrying the frozen prose, worst-to-newest by tag.
# A row leaves this file when that release's body is rebuilt from its own
# CHANGELOG entry. The ceiling may only fall.
#
# A release that is **deliberately left alone keeps its row**, with the reason
# after the tag. It does not become an exemption in code. An exemption inside a
# guard is a decision nobody reads again; a row with a reason is a decision
# that stays in front of the next person to open this file. That is the same
# argument every other record in this estate is built on.
#
# ## The one row that is already correct
#

# v0.24.0 notes, which is right for v0.24.0 and wrong for the 411 releases that
# inherited it. It carries its reason below, and it is the row most likely to
# be edited by reflex.
