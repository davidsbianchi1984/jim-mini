# English strings on the screens behind a translated tab bar, per shell.
# Checked by test_the_tabs_are_translated_and_the_screens_are_not.py, and
# ratcheted in both directions: the count may not rise, and the record may not
# sit more than 20 above the real number.
#
# This is a measurement, not a claim. The sibling product's console guard
# (test_the_nav_is_translated_and_nothing_behind_it_is.py) found forty-six
# translated sidebar labels in front of 1577 English screens and made the same
# choice: record it honestly rather than pretend.
#
#     asked     is the chrome localized
#     mattered  is anything behind the chrome localized
#
# What came off these numbers this round is the **alarm surface** — fourteen
# strings across all three shells, in ten languages, checked by name rather
# than by count in `test_the_alarm_surface_is_translated_on_every_shell`.
# That subset was chosen because it is where English is a hazard rather than a
# discourtesy: the question the crash watch asks, the three answers to an open
# alarm, and the line saying this screen cannot call an ambulance.
#
# The rest is ordinary product prose. It is not fine, and it is next.
#
# The Windows count is the largest of the three because that shell puts its
# wording in XAML attributes, which cannot be re-read when the language
# changes. Localizing a Windows string means moving it to the code-behind
# first — which is why the alarm surface there gained a LocalizeAlarmSurface()
# rather than a table lookup in place.

# **Corrected in 0.30.9.** The numbers first recorded here counted any string
# literal containing a letter, which counted format fragments like
# `"\(dim): \(n)%"` — whose only letters are variable names nobody reads — as
# English prose. Roughly seventy-five of them across the nine shells.
#
#     asked     does this literal contain letters
#     mattered  does this literal contain words a reader reads
#
# The ratchet caught it by firing on a card that had just been fully
# localized, which is a measurement saying the opposite of the truth. The
# counts below are what is actually unreadable.

# **Corrected in 0.47.1, and the safety surface carved out.** The guard in
# this repo is the sibling's guard, copied — so the blind spot it found was
# here too: a string chosen by a ternary is not at the start of an argument
# list, and nothing was looking anywhere else. The recorded numbers were
# understating by 40.
#
# What that hid is the part worth writing down. The fourteen `alarm.*` rows
# carved out earlier localize what the alarm *says* once it is going. They do
# not localize **Tap for emergency**, **Arm the crash watch**, **Issue Medical
# ID** or **Rotate QR** — the controls that arm it, fire it and stand it down
# — because the count those rows were chosen from could not see them.
#
#     asked     is the alarm's own wording localized
#     mattered  is the control that starts it
#
# This round takes the whole safety surface on all three shells: the SOS
# control, the crash-watch dial, the autonomous-resuscitation waiver, the
# responder card, first aid, the monitor and the custody proof. Also settled:
# the SOS button read *Tap for emergency* on the phones and *Click for
# emergency* on the desktop, and the escalation-floor sentence dropped the
# word *language* on one shell out of three.

# **0.47.2 — Family and Connect, on all three shells at once.**
#
# Family is where a parent enrols a child, picks how much of that child's
# record they get to see, and reads the sentence saying the auto-defibrillation
# waiver can never be signed for a minor. That sentence was English on every
# shell. So were the oversight tiers, and so was the scope on the card that
# confirms a new child's account — which on Android and Windows was not even
# English but the API's own enum member, `full` and `alerts_only`, printed raw
# on a parent's screen.
#
# Connect is the door out to QRME's community, and the three promises on it —
# *Mirror the conversation here*, *Post on your behalf*, *Share your health
# data* — were arguments to a helper rather than the first thing in a `Text(`,
# so no ratchet on any shell could ever have counted them.
#
#     asked     is the wording on the screen in the table
#     mattered  can the measurement see the wording at all
#
# Two more of the same shape came off with them: the sensitivity dial rendered
# `cautious`/`balanced`/`assertive` by capitalizing the API value on iOS and
# Android (Windows has asked the table for those three rows for rounds), and
# ConnectView's tab strip rendered an enum's raw values, where English lives in
# a `case` clause no pattern here looks at. Three more such enums remain, on
# Care, Life and Safety, and they belong to the rounds that take those screens.

# **0.47.4 — Overview, and the strips that showed enum members.**
#
# Overview is the first screen a person sees after signing in: the greeting,
# the language they will be spoken to in, the model that will do the speaking,
# what the Guardian has learned about them, and whether they are enrolled
# under their own name. All of it was English on all three shells.
#
# The tab strips on Care, Life and Safety were the shape written down at
# 0.47.2 and left for the round that takes those screens — English in a `case`
# clause of `enum Tab: String`, where no `Text("…")` pattern looks. So was the
# feedback picker, whose five choices were the API's own values with a capital
# letter put on the front.
#
#     asked     is the wording on the screen in the table
#     mattered  is the wording anywhere a pattern can reach
#
# Three names for one screen came out of it. The empty-baseline line sent a
# reader to *Monitor* on the phones and *Live Monitoring* on the desktop,
# while the nav item itself says **Live Monitoring** — so the row now names
# the screen with a hole and fills it from `tab.monitor`, and cannot drift
# again. The Life strip said *Shop* and *Circle* where the backend's own label
# sets say *Shops* and *Your circle*, which the desktop has been rendering all
# along.
