# ## Not all of these are wrong
#
# PDI has no plans, no memberships and no emailed signup, so it carries none
# of the guards around them, and it never should. The rows are recorded rather
# than fixed for the same reason every backlog in this estate is: telling a
# deliberate difference from a forgotten port requires reading both, and a
# number nobody wrote down is a number nobody can shrink.
#
#     asked     does this product pass its own suite
#     mattered  do the three suites ask the same questions
#
# ## What the first run found
#
# 140 rows, of which four were one defect: a CORS guard existed in QRME and
# JIM-mini and not in PDI, and so did the code it guards. PDI's frozen backend
# has always opened CORS for the packaged console; `serve` — the from-source
# path — set nothing, so the installed app worked and the from-source one
# answered every console request with no access-control header at all. Fixed
# and measured over HTTP, which is the only place a CORS rule exists: an
# in-process test client never sends an Origin.
#
# Those four rows are now in shared_guards.txt. These 136 are what is left.
#
# ## A name is not a behaviour
#
# Some rows here are the same guard under a different name — PDI reports its
# version from /health, under a test called something else. Those are as much
# work to resolve as a real gap, because resolving one means reading both
# suites, which is the work this file exists to keep track of.
#
