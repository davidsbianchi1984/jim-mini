# A row here needs a reason. "The phone does not do that" is usually the
# defect rather than the reason, which is how 0.59.6 started next door: a

# comparison between clients passed because they agreed.
#
# ## The row this file used to hold, and why it was wrong
#
# `*: x-signup-key` sat here with a reason that read well and did not
# survive a real host: "a client that could present it would be a client
# that reopens the door the operator shut." But JIM_SIGNUP_KEY is not a
# lock, it is an invitation — the operator sets it and then *hands it to
# the people they invite*, and the backend's own refusal says "send it as
# the x-signup-key header." With no client able to present it, the first
# published deployment collected whole signup forms and answered each one
# with a 403 nobody could act on — including the operator's. Every client
# now stores an invite key and presents it, the signup screens ask for one
# exactly when /health says the deployment is gated, and this file goes to
# zero the way a backlog should: by the gap closing, not the reason
# improving.
